# MCP 에이전트 1회 사이클 — 복사·붙여넣기용 인풋 프롬프트

**새 세션에서 사용 시**: 이 파일만 참조하거나, 아래 프롬프트 블록만 붙여넣어도 됩니다. 에이전트는 **먼저 [docs/figma/MCP_AGENT_FULL_ROADMAP.md](docs/figma/MCP_AGENT_FULL_ROADMAP.md)를 읽은 뒤**, 그 문서의 A→B→C→D→E→F 순서와 참조 문서 스위트에 따라 1회 사이클만 수행하세요.

**사용법**: 아래 블록을 복사한 뒤, **`[섹션]`** / **`[nodeId]`** / **`[라우트]`** 만 현재 진행할 사이클에 맞게 바꿔 넣고, 채팅에 붙여넣기하면 된다. 에이전트는 로드맵(MCP_AGENT_FULL_ROADMAP.md)을 1차로 확인하고, 아래 1회 사이클을 **A→B→C→D→E→F 순서로만** 진행한다.

---

## 복사·붙여넣기용 프롬프트 (템플릿)

```
이번 1회 사이클을 진행해줘.

- **섹션**: [섹션]
- **nodeId (최대 3개, 순차 MCP 호출)**: [nodeId]
- **대표 라우트**: [라우트]

진행 규칙:
1) **먼저** docs/figma/MCP_AGENT_FULL_ROADMAP.md를 읽고, 그 문서의 A→F 단계와 §3 31 사이클 표를 확인한 뒤, 코드베이스 구혀사항(라우트·FIGMA_MCP_TO_CODE_CONVERSION·IA·API/ERD SSOT)을 확인한다.
2) 규칙에 따라 위 nodeId에 대해 get_design_context(필요 시 get_metadata)를 단계·순차 호출하고, 반환 데이터를 누락 없이 보관한다.
3) 반환 데이터를 바탕으로 디자인을 구현한다(px 단위, Figma SSOT). 문서 스위트(API/ERD)를 참조한다.
4) 1차 구현 후 문서 스위트로 검토하고, get_screenshot으로 Figma와 비교해 세부 조정 및 감사 검토를 한다.
5) MCP_CYCLE_LOG 등 체크리스트와 API/ERD를 갱신한다.
6) 마지막에 npm run build로 디버깅 및 필요 시 리팩토링한다.

한 사이클만 수행하고, A→B→C→D→E→F 순서를 지켜줘.
```

## IA 명칭만으로 치환할 때 (페이지 이름 기준)

섹션·nodeId 대신 **IA 명칭**만 바꿔 쓰고 싶을 때는, [IA_FSD_COMPLETE_VERIFICATION_20260208.md](IA_FSD_COMPLETE_VERIFICATION_20260208.md) §3 또는 [FIGMA_IA_FSD_STRUCTURE.md](FIGMA_IA_FSD_STRUCTURE.md)에서 해당 페이지의 nodeId·라우트를 찾아 위 템플릿의 `[섹션]`, `[nodeId]`, `[라우트]`에 넣으면 된다.

**예시 (섹션·페이지 명칭만 지정)**  
- `[섹션]`: §3.1 랜딩  
- `[nodeId]`: 1368:37201, 1368:37364, 1368:43715  
- `[라우트]`: `/`

이렇게 채운 한 줄을 프롬프트 블록에 넣어 붙여넣기하면, 에이전트가 동일한 1회 사이클(A→F)을 수행한다.
