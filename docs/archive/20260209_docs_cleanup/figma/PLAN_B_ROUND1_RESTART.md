## 4. 에이전트별 복사·붙여넣기 프롬프트 (라운드 1, 플랜 B)

**현재 경로 기준(VERIFICATION_TABLE 반영)**: [ROUND1_AGENT_PROMPTS.md](ROUND1_AGENT_PROMPTS.md) 참조. 아래 블록은 픽스 전 파일명 기준이며, 참조 스크린샷 경로가 갱신된 프롬프트는 ROUND1_AGENT_PROMPTS.md를 사용한다.

아래 블록을 각 에이전트에게 **부여 직전** 복사해 붙여넣기하면 된다. MCP는 사용하지 않고, 참조 스크린샷 경로만 사용한다.

### 에이전트 A용 (라운드 1, 사이클 1, 플랜 B)

```
이번 1회 사이클을 진행해줘. 플랜 B: MCP 대신 로컬 스크린샷을 디자인 SSOT로 사용한다.

- **에이전트 식별자**: 에이전트 A (§3.1 랜딩·§3.4 차량 목록·§3.7 일반 판매 담당)
- **라운드**: 1
- **섹션**: §3.1 랜딩
- **nodeId**: 1368:37201, 1368:37364, 1368:43715
- **참조 스크린샷 (FIGMASCR0208/§3.1_랜딩/)**: §3.1_1368-37201_랜딩페이지_Hero중심.png, §3.1_1368-37201_랜딩페이지_Hero중심-1.png, §3.1_1368-37201_랜딩페이지_Hero중심_ref.png / §3.1_1368-37364_랜딩페이지_동일구조.png, §3.1_1368-37364_랜딩페이지_동일구조-1.png ~ -4.png / §3.1_1368-43715_랜딩페이지_알림노출.png
- **대표 라우트**: /

진행 규칙 (플랜 B):
1) docs/figma/PLAN_B_SCREENSHOT_BASED.md를 읽고, FIGMASCR0208 내 참조 스크린샷 경로를 확인한다.
2) 위 참조 스크린샷을 열어 디자인을 확인한 뒤, 해당 라우트(/)를 스크린샷에 맞게 구현 또는 수정한다(px, FIGMA_MCP_TO_CODE_CONVERSION·IA·API/ERD 참조).
3) npm run build 실행, 에러 시 수정. npm run dev 후 해당 라우트 접속해 러닝 스크린샷 캡처.
4) 참조 스크린샷 vs 러닝 스크린샷 비교 → 차이 정리 → 디버깅·리팩토링.
5) MCP_CYCLE_LOG 등 체크리스트 갱신(에이전트 A, 라운드 1, 시간 명시). 보고: 담당 사이클, 참조 스크린샷 경로, 수정 파일, 비교 요약, 남은 이슈.

한 사이클만 수행하고, A→B→C→D→E→F 순서는 플랜 B에 맞게 "참조 스크린샷 확인 → 구현 → 빌드 → dev·캡처 → 비교·디버깅 → 로그·보고"로 진행해줘.
```

## 5. 태스크 부여 순서 제안

1. **사전 검토**: §3 체크리스트대로 문서·FIGMASCR0208 확인.
2. **에이전트 A/B/C 병렬 또는 순차**: 동시에 세션을 쓰면 §4의 A/B/C 프롬프트를 각각 다른 에이전트 세션에 붙여넣기. 순차로 하면 A → B → C 순으로 한 번에 한 명씩 부여.
3. **보고 수집 후**: 감사 에이전트가 코드·빌드·E2E 검수 후 [MCP_AUDIT_AGENT_LOG.md](MCP_AUDIT_AGENT_LOG.md) 갱신, 라운드 2 태스크(플랜 B용 참조 스크린샷 경로 포함) 제시.
