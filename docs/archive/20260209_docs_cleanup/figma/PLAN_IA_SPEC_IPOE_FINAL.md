## Phase 0. FIGMASCR0208 참조 폴더 재구축 (선행)

사이트맵 위계에 따라 **폴더 구조를 재구축**하고, **사이트맵에 없는 노드/이미지는 삭제**한다.

### 0.1 원칙

- **유지**: 사이트맵에 등장하는 노드에 대응하는 이미지 파일만 유지.
- **삭제**: 사이트맵에 없는 파일·폴더는 과감히 삭제.
- **폴더 구조**: 사이트맵 경로를 반영한 계층으로 재구축(아래 0.2 참고).

5. 기존 §3.x 단위 폴더(§3.1_랜딩, §3.2_회원가입 등)는 **삭제**(이미지를 새 구조로 옮긴 뒤).
6. (선택) 루트에 README 또는 INDEX.md 추가 — “본 폴더는 사이트맵 위계(PLAN_IA_SPEC_IPOE_FINAL §0.2)에 따라 재구축됨. 노드 명칭 SSOT는 사이트맵” 명시.

## Phase 1. IA 기능명세 신규 문서 작성

### 1.1 산출물

| 항목 | 내용 |
|------|------|
| **파일** | `docs/figma/IA_SITEMAP_SPEC_IPOE.md` — 신규 생성 |
| **노드 명칭 SSOT** | **사용자 사이트맵 위계만** 사용. FIGMASCR0208은 재구축된 참조 이미지 경로로만 링크. |
| **IA 골격** | 랜딩 → 회원가입 이전 GNB → GNB 5탭 → 회원가입 → 매물등록 CTA(1~5) → 마이페이지 |
| **기능 단위** | 각 기능별 **I·P·O·E** 4블록 |
| **플로우** | 전역 플로우 1개 + 기능별 세부 플로우, Mermaid(노드 ID 공백/예약어 금지) |
| **API/ERD** | CarivDealer_api_v1.md, CarivDealer_API_ERD_Mapping.md 만 인용 |

### 1.2 I·P·O·E 정의

| 구분 | 의미 | 기재 내용 |
|------|------|-----------|
| **I (Input)** | 진입·트리거·입력 | 라우트, 로그인 여부, 사용자 입력, API 요청(api_v1·ERD_Mapping만 인용) |
| **P (Process)** | 처리 단계 | 유효성·API 호출 순서·상태 전환·사용 ERD 테이블 |
| **O (Output)** | 결과·화면·상태 | 표시 화면/라우트, API 응답 기반 UI, 저장/계산값(ERD_Mapping §계산값 참고) |
| **E (Exception)** | 예외·에러·분기 | 실패 메시지, 재시도, API message/에러(api_v1 공통 포맷) |

### 1.3 문서 구조

1. **개요** — 목적, SSOT 사이트맵, ERD/API 참조(api_v1·ERD_Mapping만), 참조 이미지 폴더(FIGMASCR0208 재구축 구조) 안내.
2. **전역 플로우** — Mermaid 1개: 진입 → 랜딩 → 비로그인/로그인 → 회원가입 유도 or GNB 5탭 → 회원가입 / 매물등록 CTA / 마이페이지 → 차량목록(1714-23434) 복귀 등. 노드 ID는 camelCase/under_score.
3. **사이트맵 계층 표** — 사용자 제시 사이트맵 그대로 경로·노드 라벨·nodeId·역할 정리. 1714-23434, 1714-22332, 1714-22874, 1714-23139는 “탭 랜딩(컨테이너)” 명시.
4. **기능별 명세 (I·P·O·E)** — 아래 기능 목록 순으로, 각 기능에 I/P/O/E 4소절 + 해당 시 **세부 플로우 Mermaid** 1개. 화면/노드 명칭은 **사이트맵에 적힌 라벨만** 사용(예: §3.1_1368-37201_랜딩페이지_로그인전_풀뷰, §3.7_1425-8153_나의매물목록_회원가입유도). 참조 이미지는 `FIGMASCR0208/01_랜딩페이지/...` 등 재구축 경로로 링크.
5. **Mermaid 규칙** — flowchart TD/LR, Start/End/Input/Task/Server/Decision; 노드 ID 공백·예약어 금지; 엣지 라벨 특수문자 시 쌍따옴표.
