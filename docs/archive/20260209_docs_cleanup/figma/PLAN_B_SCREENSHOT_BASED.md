## 3. 사이클당 입력 (에이전트에게 전달)

해당 사이클의 **nodeId 1~3개**에 대응하는 **스크린샷 파일 경로** 목록을 부여한다.  
경로는 프로젝트 루트 기준 `FIGMASCR0208/§3.x_섹션폴더/§3.x_*.png` 형태(섹션별 폴더에 있음).

**참조 스크린샷 목록**: 라운드 1은 [PLAN_B_ROUND1_RESTART.md](PLAN_B_ROUND1_RESTART.md) §2, 라운드 3은 아래 §6에 기입. 그 외 라운드는 동일 규칙으로 FIGMASCR0208 루트 파일명으로 작성.

## 4. 에이전트 1사이클 작업 절차

1. **참조 스크린샷 확인**: 해당 사이클의 참조 스크린샷(로컬 FIGMASCR0208 내 파일)을 연다.
2. **구현/수정**: 해당 라우트·페이지를 스크린샷에 맞게 구현 또는 수정(px, [FIGMA_MCP_TO_CODE_CONVERSION.md](FIGMA_MCP_TO_CODE_CONVERSION.md), API/ERD 참조만).
3. **빌드**: `npm run build` 실행, 에러 시 수정.
4. **실행·접속**: `npm run dev` 실행 후 해당 라우트 접속.
5. **러닝 스크린샷 캡처**: 담당 화면의 실제 러닝 스크린샷을 캡처(브라우저 또는 Playwright 등).
6. **비교·디버깅**: 참조 스크린샷(FIGMASCR0208) vs 러닝 스크린샷 비교 → 차이 목록 정리 → 디버깅·리팩토링·디자인 보정.
7. **로그 갱신**: MCP_CYCLE_LOG 등 체크리스트 갱신(에이전트 식별자·라운드·시간 명시). API/ERD는 참조만, 갱신하지 않음.
8. **보고**: 담당 사이클, 참조 스크린샷 경로, 수정한 파일, 비교 결과 요약, 남은 이슈.
