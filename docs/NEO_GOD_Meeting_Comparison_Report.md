# 회의록 vs NEO GOD 플로우·IA 비교 분석 리포트

**목적**: 회의록 명세(2건 교차검증)와 현재 NEO GOD 플로우·IA의 일치/불일치를 식별하고, 어느 부분에서 다른지 정리.  
**비교 기준**: 회의록 — 2026-02-02 딜러 앱 프로토타입 점검 회의, 2026-02-04 라스트 밋업. NEO GOD — Global Flow, Tab Flows, IA Sitemap, Integrated Spec Table.

---

## 1. 서론

### 1.1 비교 목적

- 회의에서 확정된 플로우·내비게이션·상태·기능과, NEO GOD 문서 및 현재 구현이 동일한지 검증.
- **두 회의록 교차검증**: 교집합(양쪽에서 동일·보강된 결정)을 위주로 반영하여 확정 요건을 명확히 함.
- 불일치 시 회의록 기준으로 명세·라우트 정합 시 참고할 갭 목록 제공.

### 2.5 두 회의록 교차검증 — 교집합 (공통 확정 사항)

아래는 **2026-02-02**와 **2026-02-04** 회의에서 모두 확정·강화된 내용이다. NEO GOD·명세 반영 시 최우선 근거로 사용.

| 영역 | 02.02 확정 내용 | 02.04 확정 내용 | 교집합 요약 |
|------|-----------------|-----------------|-------------|
| **로그인/회원가입** | 1단계 소셜(구글/카카오) 중심 구현, 기존 플로우는 유지·소셜 UI 별도 추가 | 구글·카카오 소셜 로그인 우선, 자체 ID/PW 후순위 | **소셜 로그인 우선** 일치. 신분증 단계는 02.02에서 "일단 유지(추후 용도)"로 보류. |
| **사업자/딜러 인증** | 업로드 → 승인대기 → 검증(반려 가능), API는 탐색 수준 | 사업자·매매사원 OCR+인증 API, 승인 대기→승인 후 거래 가능 | **업로드·승인대기·검증** 구조 일치. API 연동은 "가능성 탐색" 수준. |
| **검차 상태** | 임시 저장 / (임시 저장-중복됨) / 검사자 매칭 중 / 매칭 완료 / 검사 중 / 검사 완료 + **차량 보관** 상태·필터 추가 | 임시 저장(중복) / 검사자 매칭 중·완료 / 검사 중·완료 / **차량 보관** | **상태 체계 7종 + 차량 보관** 양쪽 동일. 검차 임시 저장 정의(원부 업로드~검사 신청 전) 02.02에서 명확화. |
| **필터·UI 구조** | 차량 목록 = 사이드바, 단계별(검차/거래/탁송/정산) = 상단 필터 | 차량 목록 = 좌측 사이드바, 검차/거래/탁송/정산 = 상단 필터 | **차량만 사이드바, 나머지 상단 필터** 완전 일치. |
| **판매 방식 변경 제약** | 일반: 제안 없거나 모두 거절 시만 변경. 경매: 종료 후(실질적 유찰 시만) | 경매 유찰 시만, 일반 제안 없거나 거절 시만 | **변경 조건** 동일. |
| **거래 단계 버튼** | 판매 방식 변경 / 보관(숨기기) / 삭제 / 판매가 수정 — **팝업 선택안 폐기, 버튼 분리** | 판매 방식 변경 / 판매가 수정 / 보관하기 / 삭제하기 (4개) | **4개 버튼 분리** 일치. 보관 시 "임시 저장에서 확인" 안내, 삭제 시 "재검차 필요" 경고(02.02 구체화). |
| **거래 상세 단계** | 계약금~환전 단계 UI 추가 확정, 예상 정산금액 + 검사비/탁송비 안내 | 계약금·잔금·송금·환전·정산, 검사비·탁송비 포함 표시 | **계약금→잔금→송금→환전** + **정산 예상금·비용 안내** 일치. |
| **거래 필터** | 일반 거래 / 경매 거래 / 거래 완료(판매 완료·정산 전 의미) | — | 02.02: "거래 완료" = 정산 완료가 아닌 **판매 완료(정산 전)** 로 용어 정리. |

**02.02만 명시된 확정·추가(리포트에 반영)**

- **일괄 결제(한꺼번에 결제)**: 이번 범위에서 **삭제/미구현 확정** — 기능 정의서 없음·사용자 혼란 방지.
- **판매 방식 변경 시 동의 팝업**: 일반↔경매 전환 시 "차량 상태 변경 없음" 확인 동의 팝업 추가(문구/정책 수요일까지 예정).
- **임시 저장·보관 목록 삭제 규칙**: 검사 진행 중(매칭 중/완료/검사 중)에는 삭제 불가. **임시 저장·중복됨·보관** 상태에서만 삭제 버튼 노출.

## 3. 불일치 항목 (상세)

### 3.1 전체 플로우·내비게이션 구조

| 구분 | 회의록 | NEO GOD/현재 | 차이 요약 |
|------|--------|--------------|-----------|
| 전체 플로우 | 회원가입 → 차량등록·검사 → 판매 → **거래·계약금/잔금·정산** → 탁송 → 최종 정산 | 회원가입 → 대시 → 차량/검차/제안/탁송/판매이력/정산. "거래" 단계(계약금~환전)가 플로우에 없음 | 회의록은 **거래**를 판매와 탁송 사이 독립 단계로 둠. NEO GOD은 일반판매제안(L)·판매이력(O)만 있고, "거래" 단일 탭·계약금~환전 단계 미반영. |
| 내비 탭 수·구성 | **6탭**: 차량 목록 / 검차 / **거래** / 탁송 / 정산 / **마이페이지** | **7노드**: 차량(J), 검차(K), 일반판매제안(L), 탁송 일정(M)·내역(N), 판매이력(O), 정산(P) | 회의록은 "거래" 1탭·"마이페이지" 1탭. NEO GOD은 "거래" 없음, "마이페이지" 없음, 일반판매제안과 판매이력을 분리한 구조. |

### 3.2 회원가입·인증

| 구분 | 회의록 | NEO GOD/현재 | 차이 요약 |
|------|--------|--------------|-----------|
| 로그인 1단계 | **구글·카카오 소셜 로그인 우선**, 자체 ID/PW 후순위 | 이메일·비밀번호 로그인만 문서화 | 소셜 로그인·자체 계정 우선순위 미반영. |
| 신분증·단계 순서 | **신분증 등록은 소셜 로그인 뒤** 단계로 배치 | 회원가입 step1~5에 신분증 단계·순서 명시 없음 | "소셜 로그인 → 신분증" 순서가 NEO GOD에 없음. |
| 사업자·매매사원 | OCR + 인증 API로 입력·검증 | step3 사업자 인증(verifyBusinessAPI). 매매사원증·OCR 세부는 통합 테이블에만 간단 기재 | 회의록의 OCR+진위확인 API 연계 수준이 문서에 세분화되어 있지 않음. |

### 3.3 검차(검사) 플로우

| 구분 | 회의록 | NEO GOD/현재 | 차이 요약 |
|------|--------|--------------|-----------|
| 검사비 결제 | **검사비 결제** 후 검차자 매칭. 미결제 = 임시 저장 | request→step1→step2→제출/임시저장. **검사비 결제 노드 없음** | 결제 유무에 따른 분기·매칭 전제가 플로우에 없음. |
| 검사 상태 | 임시 저장 / **임시 저장(중복됨)** / **검사자 매칭 중** / **검사자 매칭 완료** / 검사 중 / 검사 완료 / **차량 보관** | 임시저장·제출·진행중·완료 수준. "중복됨", "검사자 매칭", "차량 보관" 상태 미정의 | 회의록의 7가지 상태가 NEO GOD 플로우·명세에 반영되지 않음. |
| 주소 입력 | 우편번호 기반 주소 자동완성 API | 일정·주소 입력만 언급, 우편번호 API 미명시 | API 수준 정의 누락. |

### 3.4 차량 목록·필터

| 구분 | 회의록 | NEO GOD/현재 | 차이 요약 |
|------|--------|--------------|-----------|
| 필터 위치 | **차량 목록에만 좌측 사이드바** 필터. **검차/거래/탁송/정산은 상단 필터** | IA·플로우에 필터 위치(좌측 vs 상단) **명시 없음** | UX 결정사항이 NEO GOD 문서에 없음. |

### 3.5 판매·거래

| 구분 | 회의록 | NEO GOD/현재 | 차이 요약 |
|------|--------|--------------|-----------|
| 경매 | **48시간** 고정, **즉시판매가**(최고가 기반) | 경매 기간(일) 입력, 즉시구매(buyNow) 존재하나 48시간·즉시판매가 규칙 미명시 | 회의록의 48시간·즉시판매가 정의가 플로우·명세에 없음. |
| 판매 방식 변경 제약 | 경매→다른 방식: **유찰 시에만**. 일반→다른 방식: **제안 없거나 모두 거절 시에만** | 변경 제약 조건이 플로우·통합 테이블에 **미기재** | 정책이 명세에 반영되지 않음. |
| 거래 상세 버튼 | **4개**: 판매 방식 변경 / 판매가 수정 / **보관하기** / **삭제하기** | 일반판매·경매 플로우에 보관·삭제 버튼 **미반영** | 보관(숨기기)·삭제(영구정지 후 재검사) 정책·UI가 문서에 없음. |
| 거래 단계·정산 표시 | **계약금·잔금·송금·환전·정산** 단계 및 **검사비·탁송비 포함** 최종 입금 표시 | 거래 단계(계약금~환전)·검사비·탁송비 포함 구조 **미명시** | 회의록의 재무 투명성 요구사항이 플로우·정산 명세에 없음. |

### 3.6 탁송

## 5. 권장 후속 (회의록 기준 정합 시)

**공통(02.02·02.04 교집합 반영)**

- **내비·IA**: 내비를 회의록 6탭(차량 목록 / 검차 / 거래 / 탁송 / 정산 / 마이페이지)으로 재정의. "일반판매제안"·"판매이력"을 "거래" 탭 하위 또는 거래 탭으로 통합 검토.
- **라우트**: 마이페이지용 라우트 추가(예: `/mypage`). 거래 단계(계약금·잔금·송금·환전) 전용 화면/라우트 필요 시 추가.
- **회원가입·로그인**: 전역·탭 플로우에 "소셜 로그인(구글·카카오) 1단계" 반영. 신분증 단계는 "일단 유지"(02.02). 자체 이메일 회원가입은 후순위 표기.
- **검차**: TAB_INSPECTION·통합 테이블에 "검사비 결제" 노드·분기 추가. 상태 7종(임시 저장, 임시 저장(중복됨), 검사자 매칭 중/완료, 검사 중/완료, 차량 보관) 반영. **임시 저장·보관 목록에서 삭제 버튼**: 매칭 중/완료/검사 중에는 삭제 불가, 임시저장·중복됨·보관 상태에서만 노출(02.02). 우편번호 주소 API 명시.
- **차량 목록·필터**: IA·화면 명세에 "차량 목록 = 좌측 사이드바 필터, 검차/거래/탁송/정산 = 상단 필터" 기재. **거래 필터**: 일반 거래 / 경매 거래 / 거래 완료(의미: **판매 완료·정산 전**, 정산 완료 아님)(02.02).
- **판매·거래**: 경매 48시간·즉시판매가, 판매 방식 변경 제약(일반·경매 조건 명문화), 버튼 4개 분리(판매 방식 변경/판매가 수정/보관하기/삭제하기), 보관 시 "임시 저장에서 확인" 안내·삭제 시 "재검차 필요" 경고, **판매 방식 변경 시 "차량 상태 변경 없음" 동의 팝업**(02.02), 계약금~환전 단계 및 예상 정산금액·검사비/탁송비 안내 반영.
- **탁송**: "거래 완료(잔금 납부) 후 신청" 전제 및 상태(예약→기사 배정 중→배정 완료→진행→완료) 명시.
- **정산**: "탁송 완료 10분 이내", "검사비·탁송비 포함 최종 입금" 명시.
- **마이페이지**: 전역 플로우·IA·탭 플로우에 마이페이지 추가. "조회 전용, 사업자·매매사원 정보 수정 불가(문의 기반)" 정책 기재.

**02.02 추가 반영**

- **일괄 결제(한꺼번에 결제)**: 기능 정의서 없음·혼란 방지로 **미구현/삭제 확정**. 명세·플로우에 "이번 범위 제외" 표기.
- **거래 완료 용어**: "거래 완료" = 정산 완료가 아닌 **판매 완료(정산 전)** 로 정리하여 필터·문서에 통일.

위 항목은 두 회의록과 NEO GOD·라우트를 맞출 때 필요한 작업 목록이며, 구체적 문서 수정·코드 반영은 별도 작업으로 진행하면 됨.
