이 디자인은 프로젝트의 Figma SSOT 워크플로에 따라 구현한다.

[중요] MCP 호출 금지 · 저장된 파일만 사용
- get_metadata, get_design_context, get_screenshot 등 Figma MCP를 호출하지 않는다.
- docs/figmaMCP/mcp_outputs/{nodeId하이픈}/ 에 metadata_raw.txt, design_context_raw.txt가 채워져 있거나, 파일 안에 외부 경로(예: agent-tools\<uuid>.txt) 한 줄만 있으면 그 경로를 read_file로 열어 사용한다.
- 구현·계획·에셋 추출의 근거는 read_file로 읽은 내용만 사용한다.
- design_context_raw.txt가 길면 offset/limit으로 앞·중간·뒤를 나눠 읽고 종합한다.

1) URL에서 식별자 추출
- Figma URL에서 fileKey와 nodeId를 추출한다. node-id=1444-7928 형식이면 nodeId 하이픈은 1444-7928이다.

2) 문서 기준
- docs/figmaMCP/README.md, WORKFLOW.md, NODE_TO_ROUTE_AND_FILE.md, MCP_RESPONSE_CHECKLIST.md
- docs/figma/FSD_IA_NODEID_SSOT.md §4 (코드 참조 → scope)

3) mcp_outputs 파일 읽기
- metadata_raw.txt, design_context_raw.txt를 read_file로 읽는다. 외부 경로 형태면 해당 경로를 read_file로 연다.

4) Phase 0~7 워크플로
- Phase 0: NODE_TO_ROUTE_AND_FILE.md로 라우트·페이지·FIGMASCR0208 경로 확정.
- Phase 1: metadata_raw.txt 읽기 → 체크리스트 A·B 확인.
- Phase 2: design_context_raw.txt 읽기(구간별) → 에셋 URL·생성 코드·스타일·위치·크기 추출.
- Phase 3: FIGMASCR0208 이미지 경로 확정, mcp_outputs 스크린샷과 비교. 불일치 시 Figma 기준.
- Phase 4: impl_plans/{nodeId}_구현계획.md 작성. 레이아웃 스펙(노드별 x,y,width,height) 테이블 포함.
- Phase 5: 에셋 다운로드 → src/shared/figma_image/ 저장 → 대상 컴포넌트 import·JSX 연동 → FIGMA_ASSET_TRACEABILITY.md 갱신.
- Phase 6: 레이아웃 스펙·design_context 기준으로 리팩토링. JSDoc·주석 추가. 레이아웃 충실도 검증.
- Phase 7: npm run build 검증 → docs/figmaMCP/figMCP.MD 6하원칙 로그 추가.

5) SSOT·Scope
- FSD_IA_NODEID_SSOT.md §4의 "코드 참조" 컬럼에서 해당 nodeId의 TSX 경로를 확인한다. figma-design-audit 검증기는 이 매핑으로 scope를 결정한다.

6) Tailwind
- 프로젝트에 Tailwind가 없으면 추가하지 않는다. MCP Tailwind는 design-tokens·기존 CSS로 변환한다.

7) 에셋·레이아웃 반영 (필수)
- design_context 에셋 URL → 다운로드 → import → JSX 연동. 다운로드만 하지 말 것.
