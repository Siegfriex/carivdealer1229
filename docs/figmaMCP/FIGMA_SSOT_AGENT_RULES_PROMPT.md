# Figma SSOT 에이전트 규칙 — 프롬프트 (복사용)

**목적**: CTA 1·2·3·4 등 기존 작업에서, 에이전트가 노드별 메타데이터·디자인컨텍스트를 **임의로 스킵하거나 선택 반영**하지 않도록 하기 위함. **단일 Figma SSOT**를 정확히 참조해 코딩하는 단계별·세세한 규칙을 프롬프트 형식으로 제공.

---

## 사용법

- 구현 작업 시작 전 또는 작업 지시와 **함께** 아래 "에이전트에 줄 프롬프트" 블록 전체를 복사해 붙여넣는다.
- 여러 노드(예: CTA_4 10노드)를 한 번에 다룰 때는 **대상 nodeId 목록**을 명시한 뒤 이 규칙을 붙인다.

---

## 에이전트에 줄 프롬프트 (복사용)

```
[Figma SSOT 구현 규칙 — 반드시 준수]

이번 작업에서 Figma는 **단일 정보원(SSOT)** 이다. 사용자가 정리해 둔 **노드별 metadata와 design_context** 를 임의로 스킵하거나 일부만 반영하지 말고, 아래 단계를 **순서대로 전부** 수행한다.

——— 1. 대상 노드 확정 ———
- 작업 지시에 nodeId(예: 1714-22874, 1272-12926) 또는 CTA/플로우(예: CTA_4 10노드)가 있으면, 해당하는 **모든** nodeId 목록을 docs/figmaMCP/NODE_TO_ROUTE_AND_FILE.md, impl_plans(예: CTA_4_탁송_플로우_요약.md) 등에서 확인한다.
- **목록에 있는 노드는 하나도 빠짐없이** 다음 단계에서 다룬다. "일부만 적용" 또는 "대표 노드만" 같은 선택 반영은 금지한다.

——— 2. 노드별 파일 읽기 (필수, 스킵 금지) ———
각 nodeId에 대해:
- docs/figmaMCP/mcp_outputs/{nodeId하이픈}/metadata_raw.txt 를 **반드시 read_file로 전부 읽는다.**
- docs/figmaMCP/mcp_outputs/{nodeId하이픈}/design_context_raw.txt 를 **반드시 read_file로 읽는다.** (파일이 매우 길면 offset/limit으로 구간별로 여러 번 읽어 전부 본다.)
- design_context_raw.txt 내용이 한 줄이고 그 줄이 외부 파일 경로(예: C:\...\agent-tools\<uuid>.txt)이면, **그 경로를 read_file로 열어** 실제 design_context로 사용한다. "파일이 없다"고 하지 않는다.
- **이 단계를 생략하거나, "이미 알고 있음"으로 넘어가거나, 일부 노드만 읽는 행위는 금지한다.**

——— 3. 노드별 추출 의무 (metadata) ———
읽은 metadata_raw.txt에서 **해당 노드(및 자식 노드)의 레이아웃 수치**를 추출한다.
- frame/rectangle/text 등 각 요소의 id, x, y, width, height 륌 **테이블로 정리**한다.
- 이 테이블은 impl_plans에 "레이아웃 스펙" 또는 "노드별 (x,y,width,height)" 섹션으로 **반드시** 문서화한다. (기존 impl_plans 파일이 있으면 그 파일에 섹션을 추가·갱신한다.)
- **픽셀 값(width, height, x, y)을 임의로 바꾸거나 무시하지 않는다.** 디자인에 320×420이면 코드에도 320×420(또는 w-[320px] h-[420px])으로 반영한다.

——— 4. 노드별 추출 의무 (design_context) ———
읽은 design_context(또는 경로로 열은 파일)에서 다음을 **전부** 추출한다.
- **문구·라벨·플레이스홀더**: 모든 title, tab, placeholder, 버튼 텍스트. 이 텍스트를 코드에서 **그대로** 사용한다. 임의로 요약하거나 바꾸지 않는다. (예: "주소를 검색해 주세요", "도로명, 지번, 건물명 검색", "잠시만 기다려 주세요")
- **위치·크기 클래스**: left, top, width, height, rounded, gap 등. 구현 시 **동일 픽셀 또는 동일 시각**이 나오도록 Tailwind/CSS에 적용한다.
- **색상·폰트·쉐도우**: hex/rgba, font-size, shadow 값. 프로젝트 design-tokens에 매핑하되, 수치는 design_context와 일치시킨다.
- **에셋 URL**: 이미지·아이콘 URL이 있으면 다운로드 후 src/shared/figma_image/ 등에 저장하고, **해당 컴포넌트에서 import·JSX 연동**까지 한다. "문서만 갱신"으로 끝내지 않는다.

——— 5. 구현 전 체크리스트 (노드별) ———
각 nodeId에 대해, 구현에 들어가기 전에 다음을 **문서 또는 메모**로 적는다.
- [ ] metadata에서 추출한 (x, y, width, height) 테이블을 작성했는가?
- [ ] design_context에서 추출한 문구·플레이스홀더·라벨 목록을 작성했는가?
- [ ] 해당 노드가 매핑된 라우트·페이지·컴포넌트 파일을 확인했는가?
- **체크리스트를 모두 채운 뒤에만** 코드 수정을 시작한다.

——— 6. 구현 시 적용 규칙 ———
- **레이아웃**: metadata/design_context에 적힌 width, height, x, y, gap, rounded, shadow 를 **그대로** 적용한다. "비슷하게" 또는 "대략"으로 대체하지 않는다. (예: 514×640 모달 → w-[514px] h-[640px], 320×420 패널 → w-[320px] h-[420px], gap 15/36 → gap-x-[15px] gap-y-[36px])
- **텍스트**: design_context에 있는 문구를 **한 글자도 바꾸지 않고** 사용한다. 새로 만든 문구로 대체하지 않는다.
- **선택 반영 금지**: "주요 노드만", "일부만 반영" 같은 판단을 하지 않는다. 사용자가 정리한 노드 목록에 포함된 노드는 **전부** 위 규칙에 따라 반영한다.

——— 7. 구현 후 검증 ———
- 구현한 페이지/컴포넌트에서, 해당 노드의 **주요 자식 노드**에 대해: metadata/design_context의 width·height·위치·문구가 코드에 적용되었는지 **항목별로** 확인한다.
- 갭이 있으면 (예: "제목 28px인데 24px로 되어 있음") **즉시 수정**한다. "나중에" 또는 "선택 사항"으로 남기지 않는다.
- docs/figmaMCP/impl_plans 아래에 **갭 분석 문서**(예: CTA_4_10노드_디자인_반영_갭.md)가 있으면, 그 표의 "미반영·보완" 항목을 하나씩 해소한 뒤 완료로 표시한다.

——— 8. 금지 사항 (절대 하지 말 것) ———
- metadata_raw.txt 또는 design_context_raw.txt를 **읽지 않고** "일반적인 레이아웃"으로 구현하는 행위.
- 노드 목록이 주어졌는데 **일부 노드만** 읽고 나머지는 스킵하는 행위.
- 디자인에 명시된 **픽셀·문구를 임의로 변경**하거나 "비슷한 값"으로 대체하는 행위.
- "이미 구현되어 있다"고 가정하고 metadata/design_context를 **재검증하지 않는** 행위.
- 에셋을 다운로드만 하고 **컴포넌트에 import·연동하지 않는** 행위.

작업 완료 보고 시, "어떤 노드의 metadata/design_context를 읽었는지", "추출한 레이아웃 스펙 테이블을 어디에 반영했는지", "갭 문서의 미반영 항목을 몇 개 해소했는지"를 명시한다.
```

## 요약: 에이전트가 꼭 할 일

| 단계 | 할 일 | 금지 |
|------|--------|------|
| 1 | 대상 nodeId **전부** 목록 확정 | 일부만 선택 |
| 2 | **모든** nodeId에 대해 metadata_raw.txt + design_context_raw.txt read_file | 스킵·생략 |
| 3 | metadata → 노드별 (x,y,width,height) 테이블 작성·문서화 | 수치 임의 변경 |
| 4 | design_context → 문구·위치·크기·색·에셋 **전부** 추출 | 문구·수치 임의 변경 |
| 5 | 구현 전 노드별 체크리스트 작성 | 체크 없이 코딩 |
| 6 | 코드에 **동일 픽셀·동일 문구** 적용 | "비슷하게" 대체 |
| 7 | 구현 후 항목별 검증·갭 해소 | 미반영 항목 방치 |
| 8 | — | 선택 반영·스킵·가정 |

## 한 번에 복사할 프롬프트 (압축 버전)

아래 블록을 작업 지시 **맨 뒤**에 붙여 넣어 사용한다.

```
[Figma SSOT] 단일 Figma SSOT 준수. 노드별 metadata·design_context를 스킵·선택 반영 금지.
1) 대상 nodeId 전부 목록 확정(일부만 선택 금지).
2) 각 nodeId마다 mcp_outputs/{nodeId}/metadata_raw.txt + design_context_raw.txt(또는 내부 경로) 반드시 read_file. 생략 금지.
3) metadata → 노드별 (x,y,width,height) 테이블 추출 후 impl_plans에 레이아웃 스펙으로 문서화.
4) design_context → 모든 문구·플레이스홀더·라벨·위치·크기·색·에셋 추출; 문구는 그대로, 픽셀은 그대로 적용.
5) 구현 전 노드별 체크리스트(레이아웃 테이블·문구 목록·매핑 파일) 작성 후에만 코딩.
6) 구현 시 metadata/design_context 수치·문구 동일 적용. "비슷하게" 대체 금지.
7) 구현 후 항목별 검증·갭 문서 미반영 항목 해소.
8) 금지: 읽지 않고 구현, 일부 노드만 다룸, 픽셀·문구 임의 변경, 에셋 다운로드만 하고 연동 안 함.
완료 시 "어떤 노드를 읽었는지·레이아웃 스펙 반영 위치·갭 해소 수" 명시.
```
