# FIGMASCR0208 이미지 기반 검증 프로토콜

**목적**: 각 스크린샷 이미지를 IA §3 "페이지"·nodeId와 대조하여 올바른 섹션·파일명을 부여하고, 섹션별 폴더로 구조화한다.

**기준 SSOT**: [docs/figma/IA_FSD_COMPLETE_VERIFICATION_20260208.md](../docs/figma/IA_FSD_COMPLETE_VERIFICATION_20260208.md) §3 (페이지 | nodeId | 라우트 표).

---

## 1. 검증 수행 주체 및 도구

- **옵션 A (권장)**: 사람이 각 이미지를 열어 UI 요소(탭 이름, 버튼 문구, 리스트/그리드 여부, 헤더·사이드바 유무 등)를 보고 IA §3 "페이지" 설명 및 nodeId와 매칭.
- **옵션 B**: 이미지 인식 가능 에이전트가 "화면 내용 요약 → IA 페이지 후보 매칭" 후, 불확실한 것만 사람이 최종 확정.

---

## 2. 검증 순서 (IA §3 순서 유지)

1. **§3.1 랜딩** (3 nodeId): Hero 중심 / 동일 구조 / 알림 노출 구분.
2. **§3.2 로그인·회원가입** (9): 로그인, 회원가입 Step1~5, 승인대기, 승인완료, 진입 등.
3. **§3.3 대시보드** (1): 대시보드 1종 (스크린샷 없을 수 있음).
4. **§3.4 차량 목록** (13): 기본, 전체탭, 임시저장, 등록완료, 그리드, 리스트, 검색, 확인필요, Empty, 페이지네이션, 카드/상태, 필터바, 정렬.
5. **§3.5 차량 등록·상세·경매** (14): 차량등록진입, 경매 시작가, 거래목록, 거래상세, 경매 만료 등.
6. **§3.6 검차** (9): 검차신청 Step1, 요청내역 리스트/완료탭/카드뷰, 진행(매칭중/픽업/완료), 결과 요약/상세.
7. **§3.7 일반 판매** (9): 나의 매물 목록(전체, 검차필터, 판매/가격제안, 탁송필터, 정산), 일반판매 등록/완료/원부 등.
8. **§3.8 마이페이지** (12): 내 프로필, 기본정보수정, 딜러승인(승인완료/대기/반려), 정산계좌, 사업자정보, 알림센터/설정 등.
9. **§3.10 탁송** (11): 물류스케줄, 탁송목록, 탁송신청/완료, 새 탁송 예약(주소/폼/달력/시간) 등.
10. **§3.11 정산** (4): 정산목록, 정산상세, 정산현황(검차피드백/진행상황).

## 3. 단계별 절차

| 단계 | 행동 | 산출 |
|------|------|------|
| 1 | FIGMASCR0208 루트의 PNG 목록 확보 | current_file 목록 |
| 2 | IA_FSD §3 열어 섹션별 "페이지"·nodeId 표 확인 | 대조용 기준표 |
| 3 | **섹션별로** 해당 §의 이미지들만 골라 이미지 열기 | — |
| 4 | 화면 내용(탭, 버튼, 리스트/그리드, 헤더 등)과 IA "페이지" 설명 대조 | nodeId·IA페이지명 확정 |
| 5 | 동일 nodeId에 여러 이미지면 기본이름.png, -1.png, -2.png 접미 | new_filename 확정 |
| 6 | current_file → section, nodeId, new_folder, new_filename 를 테이블에 기입 | VERIFICATION_TABLE |
| 7 | IA에 대응 안 되는 이미지는 new_folder=`_ref`, note=no_match | 테이블 보완 |

## 4. 섹션별 판단 기준 (예시)

- **§3.1**: Hero 중심 = 메인 히어로 영역 강조 / 동일 구조 = 랜딩이지만 구조만 동일 / 알림 노출 = 알림 아이콘·배지 등 노출.
- **§3.4**: 전체 탭 = 탭에 "전체" 또는 filter=all 느낌 / 등록완료 = 완료 상태 표시 / 그리드 = 카드 그리드 / 리스트 = 리스트 뷰 / Empty = 목록 비어 있음.
- **§3.5**: 경매 시작가 설정 = 입력 필드·시작가 UI / 거래 상세 (경매) = 상세 카드·경매 상태 / 판매·거래 목록 = 목록·테이블.
- **§3.7**: 나의 매물 목록 → 탭·필터 라벨로 "전체·상태" vs "검차" vs "판매/가격제안" vs "탁송" vs "정산" 구분.
- **§3.8**: 딜러 승인 → "승인완료" vs "승인대기" vs "반려" 문구/상태로 37042/37170/37677 구분.

## 5. 검증 테이블 컬럼 정의

| 컬럼 | 설명 |
|------|------|
| current_file | 현재 FIGMASCR0208 루트 기준 파일명 |
| section | IA § 번호 (예: §3.4) |
| nodeId | Figma nodeId (예: 1418:15565) |
| ia_page_short | IA 페이지명 요약 (파일명에 쓸 형태) |
| new_folder | 배치할 섹션 폴더명 (예: §3.4_차량목록) |
| new_filename | 최종 파일명 (IA 규칙. 동일 nodeId 복수 시 -1, -2) |
| note | 검증 근거 또는 no_match, ref_only 등 |
