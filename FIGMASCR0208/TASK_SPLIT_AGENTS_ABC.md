# §3.2~§3.11 스크린샷 점검 — 에이전트 A/B/C 병렬 태스크 분할

**목적**: 각 에이전트가 담당 이미지를 **명확히 확인**한 뒤, GNB·맥락 기반으로 리네이밍 의견을 **텍스트로만** 보고.  
**실제 파일 이동/리네임은 하지 않음** — 보고 수집 후 상위에서 일괄 적용.

---

## 공통 프로토콜 (A/B/C 동일)

1. **이미지 확인**  
   담당 목록의 각 PNG를 **실제로 열어** 내용을 확인한다.

2. **이미지당 3단계 분석**  
   - **GNB 활성 메뉴**: 상단 글로벌 내비에서 어떤 메뉴가 활성(강조)인지 (차량목록 / 검차 / 거래 / 탁송 / 정산 / 없음 등).  
   - **맥락 순 분석**: 화면 제목, 중앙 메시지, 버튼/폼/리스트 등으로 어떤 페이지·상태인지 파악.  
   - **IA 대조**: `docs/figma/IA_FSD_COMPLETE_VERIFICATION_20260208.md` §3 해당 섹션의 페이지·nodeId와 비교.

3. **의견 정리 (텍스트만)**  
   - 현재 파일명·폴더가 맞으면: **유지**  
   - 잘못 매핑되었으면: **제안** (이동할 섹션·폴더, 제안 파일명, 이유 1줄)  
   - 불명확하면: **확인 필요** (이유 1줄)

4. **금지 사항**  
   - 파일/폴더 이동·리네임·삭제 금지.  
   - 보고는 **텍스트만** 제출 (마크다운 표나 목록 형태 권장).

---

## 보고 형식 (에이전트가 채워서 제출)

아래 블록을 복사해, 담당 구간만 채운 뒤 **텍스트로** 제출.

```markdown

**담당**: [섹션명]
**이미지 수**: N개

### 이미지별 의견

| 현재 경로/파일명 | GNB 활성 | 맥락(한 줄) | 판단 | 제안(이동·리네임 시에만) |
|------------------|----------|-------------|------|---------------------------|
| §3.x_.../파일.png | ... | ... | 유지 / 이동·리네임 제안 / 확인 필요 | 제안 시: §3.y_폴더/§3.y_nodeId_이름.png |

### 요약
- 유지: N건
- 이동·리네임 제안: N건 (간단 목록)
- 확인 필요: N건 (간단 목록)
```
