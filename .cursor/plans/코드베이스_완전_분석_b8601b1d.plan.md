# 코드베이스 완전 분석 계획

## 분석 범위

- **Controller**: 8개 파일 (API 엔드포인트 분석)
- **Service**: 22개 파일 (비즈니스 로직 분석)
- **ParserService**: 6개 파일 (파싱 로직 분석)
- **Entity**: 도메인별 Entity + BaseEntity, TenantEntity
- **Repository**: 13개 파일 (데이터베이스 쿼리 분석)
- **전역 설정**: Security, Exception, Config, AWS S3, Upstage OCR

## 분석 단계

### 1단계: 프로젝트 구조 파악

- `build.gradle` 분석: Spring Boot 3.5.9, Java 17, 의존성 추출
- `ExpApplication.java` 분석: 메인 클래스 및 활성화된 설정
- 도메인 구조 매핑: 11개 도메인 (auction, base, document, export, invoice, login, malso, registration, upstage, vehicle, vehiclePurchase)
- 파일 카운트: Controller(8), Service(22), Repository(13), Entity(도메인별)

### 2단계: API 엔드포인트 완전 분석

**분석 대상 Controller (8개):**

- `AuthController.java` - 인증 API
- `AdminUserController.java` - 관리자 사용자 관리
- `BaseInfoController.java` - 회사 기본정보
- `DocumentController.java` - 문서 관리
- `ExportController.java` - 수출 증명서
- `MalsoController.java` - 말소 등록증
- `VehicleController.java` - 차량 관리
- `PrintController.java` - 출력/인쇄

**각 Controller별 분석 항목:**

- Base Path (`@RequestMapping`)
- Swagger Tag (`@Tag`)
- 각 메서드의 HTTP Method, 경로, 파라미터, 응답 타입
- 호출하는 Service 메서드
- 라인 번호 범위

### 3단계: Service 계층 분석

**분석 대상 Service (22개):**

- 도메인별 Service: AuctionService, BaseInfoService, DocumentService, ExportCertificateService, InvoiceService, DeRegistrationService, RegistrationService, VehicleService, AuthService, AdminUserService
- ParserService: AuctionParserService, RegistrationParserService, DeRegistrationParserService, InvoiceParserService, ExportParserService, BaseInfoOcrParserService
- 전역 Service: UpstageService, DocumentOrchestrationService, RefreshTokenService, CustomUserDetailsService, BaseInfoOcrService, MalsoPrintService

**각 Service별 분석 항목:**

- 의존성 주입 목록
- 메서드별 시그니처, 트랜잭션, 비즈니스 로직 흐름
- 호출하는 Repository/Service 메서드
- 예외 처리
- 라인 번호 범위

### 4단계: Parser 서비스 분석

**분석 대상 ParserService (6개):**

- `AuctionParserService.java` - 경매증 파싱
- `RegistrationParserService.java` - 등록증 파싱
- `DeRegistrationParserService.java` - 말소등록증 파싱
- `InvoiceParserService.java` - 세금계산서 파싱
- `ExportParserService.java` - 수출증명서 파싱
- `BaseInfoOcrParserService.java` - 기본정보 OCR 파싱

**각 Parser별 분석 항목:**

- 파싱 대상 문서 타입 및 입력/출력 형식
- 파싱 전략 (OCR, 정규표현식, DOM 파싱 등)
- 파싱 단계별 분석
- 에러 처리 방식
- 사용하는 외부 라이브러리/API

### 5단계: 데이터베이스 스키마 분석

**Entity 분석:**

- BaseEntity, TenantEntity (공통 엔티티)
- 도메인별 Entity: AuctionCertificate, BaseInfo, Documents, Export, TaxInvoice, DeRegistrationCertificate, RegistrationReCertificate, Vehicle, VehiclePurchase, User, Company, RefreshToken

**Repository 분석 (13개):**

- 각 Repository의 커스텀 쿼리 메서드 분석
- 쿼리 생성 방식 (메서드명 기반 / @Query / 네이티브)
- 예상 SQL 쿼리
- 사용 위치 추적

### 6단계: 보안 및 인증 분석

**분석 파일:**

- `SecurityConfig.java` - 필터 체인 설정
- `JwtTokenProvider.java` - 토큰 생성/검증
- `JwtAuthenticationFilter.java` - 인증 필터
- `AuthService.java` - 로그인 플로우
- `RefreshTokenService.java` - Refresh Token 관리

**분석 항목:**

- JWT 인증/인가 전체 플로우 (라인별 추적)
- 필터 체인 설정 및 인증 경로
- 토큰 만료 시간 및 발급/검증 로직

### 7단계: 예외 처리 분석

**분석 파일:**

- `ErrorCode.java` - 에러 코드 열거형
- `GlobalExceptionHandler.java` - 전역 예외 처리
- `CustomException.java` - 커스텀 예외 구조
- `DeRegistrationExceptionHandler.java` - 도메인별 예외 처리

**분석 항목:**

- 모든 에러 코드 목록 및 HTTP Status 매핑
- 예외 처리 메서드별 분석
- Service에서 사용하는 ErrorCode 추적

### 8단계: 전역 설정 및 인프라 분석

**Config 파일 분석:**

- `SecurityConfig.java`
- `SwaggerConfig.java`
- `AsyncConfig.java`
- `UpstageConfig.java`
- `AwsS3Config.java`

**외부 서비스 연동 분석:**

- AWS S3: `S3Upload.java`, `S3ObjectReader.java`
- Upstage OCR: `UpstageService.java`, OCR 호출 및 응답 처리

### 9단계: 데이터 흐름 분석

**주요 비즈니스 플로우 추적:**

1. 문서 업로드 → 파싱 → 저장 플로우

- `DocumentController.upload()` → `DocumentService` → `ParserService` → `Repository`

2. 로그인 → 토큰 발급 플로우

- `AuthController.login()` → `AuthService` → `JwtTokenProvider` → `RefreshTokenService`

3. 차량 등록 → 말소 플로우

- 관련 Controller → Service → Repository 추적

**각 플로우의 라인 번호 명시 및 다이어그램 작성**

### 10단계: 통합 문서 생성

**생성할 문서:**

1. `01_PROJECT_STRUCTURE.md` - 프로젝트 구조 및 메타데이터
2. `02_API_ENDPOINTS.md` - 모든 API 엔드포인트 명세
3. `03_SERVICES.md` - Service 계층 비즈니스 로직 분석
4. `04_PARSERS.md` - Parser 서비스 분석
5. `05_DATABASE_SCHEMA.md` - 데이터베이스 스키마 분석
6. `06_SECURITY.md` - 보안 및 인증/인가 분석
7. `07_EXCEPTION_HANDLING.md` - 예외 처리 분석
8. `08_CONFIGURATION.md` - 전역 설정 및 인프라 분석
9. `09_DATA_FLOW.md` - 데이터 흐름 분석
10. `10_SUMMARY.md` - 코드 통계 및 아키텍처 다이어그램

## 분석 원칙

- 모든 파일을 `read_file`로 완전히 읽고 분석
- 모든 메서드에 파일 경로와 라인 번호 명시
- 실제 코드 인용으로 분석 근거 제시
- Controller → Service → Repository → Entity 의존성 추적
- 주요 비즈니스 플로우를 라인 단위로 추적

## 예상 작업량

- 읽을 파일: 약 60개 이상의 Java 파일
- 분석할 메서드: 약 200개 이상
- 생성할 문서: 10개 마크다운 파일
